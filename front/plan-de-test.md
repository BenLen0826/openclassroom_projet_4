# Plan de test du front — correspondance avec les tests réalisés

Objectif : **80 % de couverture minimum** pour tous les indicateurs (instructions, branches, fonctions, lignes), avec Jest **et** avec Cypress.

Notation des tests : `Bloc describe › nom du test`
- **(U)** test unitaire Jest : le composant ou service est testé seul, ses dépendances sont mockées (`*.spec.ts`) ;
- **(I)** test d'intégration Jest : le composant est rendu avec son template et ses vrais services, seules les requêtes HTTP sont simulées avec `HttpTestingController` (`*.integration.spec.ts`) ;
- **(E2E)** test de bout en bout Cypress : l'application tourne dans un vrai navigateur, le back est simulé avec `cy.intercept` (`cypress/e2e/*.cy.ts`).

Les tests écrits avec une boucle (`forEach` en Cypress, `it.each` ou `forEach` en Jest) génèrent un test par champ : le nombre de tests générés est indiqué entre parenthèses.
